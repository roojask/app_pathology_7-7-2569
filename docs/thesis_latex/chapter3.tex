\section{การประมวลผลและวิเคราะห์ข้อมูล}

\subsection{การประมวลผลเสียงเบื้องต้น}
ไฟล์เสียงถูกกรองด้วย FFmpeg ตามลำดับ คือตัวกรอง \texttt{afftdn} \cite{ffmpeg_afftdn} ด้วยค่าเริ่มต้นของ FFmpeg ได้แก่ ลดสัญญาณรบกวน (\texttt{nr}) 12 dB ระดับเสียงรบกวนพื้นฐาน (\texttt{nf}) $-50$ dB และชนิดเสียงรบกวนแบบขาว (\texttt{nt=w}) แล้วตามด้วย \texttt{silenceremove} ที่ตัดช่วงเงียบต่ำกว่า $-40$ dB ที่ต้นไฟล์ซึ่งยาวเกิน 0.1 วินาที และช่วงหยุดพูดที่ยาวเกิน 0.6 วินาทีตลอดไฟล์ ขั้นตอนนี้ตัดตามระดับสัญญาณ ไม่ใช่แบบจำลองตรวจจับเสียงพูด (VAD) การแปลงเป็น 16 kHz Mono ทำโดยฟังก์ชันโหลดเสียงของไลบรารีถอดความ คำสั่งเต็มอยู่ในภาคผนวก ก โครงงานนี้ไม่ได้ทดลองหรือปรับค่า afftdn อื่น

\subsection{เอนจินถอดความ PathoWhisper}
ใช้ Faster-Whisper รุ่น Small (เวอร์ชัน 1.2.1) \cite{fasterwhisper} บน CTranslate2 \cite{ctranslate2} แบบ INT8 บน CPU 8 เธรด กำหนด Beam Size เป็น 1 และป้อนข้อความนำ (\texttt{PATHOLOGY\_PROMPT}) ที่รวมถ้อยคำและคำศัพท์ตามโปรโตคอล CAP สำหรับมะเร็งเต้านม (ภาคผนวก ก) โครงงานนี้ไม่ได้ Fine-tune น้ำหนักของแบบจำลอง ใช้เพียง Quantization และการปรับพฤติกรรมด้วยข้อความนำ แบบจำลองพื้นฐานคือ Whisper Small จากไลบรารี openai-whisper (PyTorch, FP32 บน CPU, Beam Size 5, ไม่ใช้ Prompt และไม่ผ่าน afftdn) ส่วน PathoWhisper ใช้ Beam Size 1 เวลาที่ลดลงจึงส่วนหนึ่งมาจากการลด Beam Size และการเปรียบเทียบนี้เป็นการเปรียบเทียบทั้งระบบ ไม่ได้แยกผลของแต่ละองค์ประกอบ

\subsection{ตัวสกัดข้อมูลทางคลินิก}
ตัวสกัดใช้นิพจน์ปรกติและกฎหน้าต่างบริบทจับคู่ข้อความกับ 15 ฟิลด์ (รายการอยู่ในภาคผนวก ข) แบบฟอร์ม 15 ฟิลด์ออกแบบจากรายการตรวจชิ้นเนื้อด้วยตาเปล่าภายใต้คำแนะนำของพยาธิแพทย์ที่ปรึกษาร่วม โดยอ้างอิงองค์ประกอบข้อมูลของโปรโตคอล CAP \cite{cap_breast} ฟิลด์ส่วนหนึ่ง ได้แก่ ด้านของเต้านม หัตถการ ตำแหน่งก้อน ขนาดก้อน ขอบตัด และต่อมน้ำเหลือง สอดคล้องกับข้อมูลหลักของโปรโตคอล ส่วนที่เหลือเป็นรายการตรวจสภาพภายนอกที่ใช้ในการบรรยายด้วยตาเปล่า เช่น หัวนม ผิวหนัง และรอยแผลเป็น ซึ่งไม่ได้อ้างอิงจากรายการข้อมูลที่ต้องรายงานของ CAP โดยตรง

ตัวปรับข้อความ (\texttt{normalizer.py}) ทำงานก่อนตัวสกัด โดยแปลงตัวพิมพ์เล็ก แทนคำเชื่อมมิติ เช่น by และ times เป็น x แทนคำพ้องความหมายบางคำเพื่อการจับคู่ (เช่น tumor และ lesion เป็น mass) และจัดการการพูดแก้ไขกลางประโยค กฎการแก้ไขมิติ 2 หรือ 3 มิติลบค่าเดิมก็ต่อเมื่อค่ามิติตามด้วยคำสัญญาณ ได้แก่ sorry, wait, no wait, weight, correction หรือ actually และคำสัญญาณนั้นตามด้วยมิติใหม่ที่มีตัวคูณ เช่น 2.0 x 3.0 x 1.0 cm sorry 2.5 x 3.5 x 1.5 cm ได้ผลเป็น 2.5 x 3.5 x 1.5 cm (รวมคำไทย เช่น แก้เป็น เปลี่ยนเป็น ไม่ใช่ ซึ่งชุดทดสอบภาษาอังกฤษไม่ได้ทดสอบ) คำว่า weight อยู่ในรายการเพราะ Whisper บางครั้งถอดคำว่า wait เป็น weight แต่เงื่อนไขว่าต้องตามด้วยมิติใหม่ทำให้ข้อความที่บอกน้ำหนักสิ่งส่งตรวจ เช่น weight 450 grams ไม่ลบมิติเดิม กฎมิติเดี่ยว เช่น 2 cm no 3 cm ใช้เมื่อค่าที่สองมีหน่วยความยาวกำกับเท่านั้น เพื่อไม่ให้วลีเช่น no 3 lymph nodes ถูกอ่านเป็นขนาด คำว่า no เดี่ยว ๆ ไม่ใช่คำสัญญาณในกฎหลายมิติ ถ้อยคำปฏิเสธ เช่น no residual tumor จึงไม่ถูกตัด รุ่นแรกของกฎมีข้อบกพร่องที่พบจากการทดสอบหน่วย (บทที่ 4) ตัวสกัดไม่ใช้แบบจำลองภาษาเชิงกำเนิดและไม่เติมค่าที่ไม่ได้ปรากฏในข้อความถอดความ หากไม่พบค่า ฟิลด์จะถูกทิ้งว่างเพื่อให้ผู้ใช้กรอกเอง

\subsection{แบบจำลองที่ใช้เปรียบเทียบ}
นอกจาก Whisper Small ยังเปรียบเทียบ Whisper Base, Whisper Tiny, Vosk \cite{vosk} และ wav2vec 2.0 \cite{baevski2020wav2vec} บนชุดย่อย 30 กรณี ที่สุ่มแบบแบ่งชั้น หมวดละ 3 กรณีจาก 10 หมวด โดย Vosk ใช้รุ่น vosk-model-small-en-us-0.15 และไม่ได้กำหนดคำศัพท์ทางการแพทย์เพิ่ม

\section{การออกแบบและพัฒนาระบบ}

ระบบเป็นเว็บแอปพลิเคชันที่พัฒนาด้วย Flask ให้บริการบนเครื่องผ่าน HTTPS (เซิร์ฟเวอร์ภายในเครื่องแบบหลายเธรด พอร์ต 7860 ใช้ใบรับรอง TLS ที่ออกเองด้วย OpenSSL ซึ่งจำเป็นเพราะเบราว์เซอร์อนุญาตให้ใช้ไมโครโฟนเฉพาะในบริบทที่ปลอดภัย) และบรรจุด้วย PyInstaller เป็นแอปพลิเคชันสำหรับเครื่องเดสก์ท็อป ส่วนหน้าบันทึกเสียงจากไมโครโฟนผ่านเบราว์เซอร์ ส่วนหลังบ้านเรียกขั้นตอนกรองเสียง ถอดความ และสกัดข้อมูล แล้วแสดงผลให้ผู้ใช้ตรวจทานและแก้ไขก่อนยืนยัน ข้อมูลที่ยืนยันแล้วบันทึกลง PostgreSQL 16 ผ่าน Flask-SQLAlchemy และสำรองลง SQLite (\texttt{pathology.db}) โดยสลับไปใช้ SQLite อัตโนมัติเมื่อเชื่อมต่อ PostgreSQL ไม่ได้ ฐานข้อมูลมีตารางผู้ใช้ (รหัสผ่านเก็บแบบเข้ารหัส) ตารางประวัติแบบฟอร์มที่ลบแบบซ่อน (Soft Delete) เพื่อคงประวัติ และตารางเวอร์ชันการแก้ไขที่เก็บทุกครั้งที่ผู้ใช้แก้ฟิลด์ เพื่อใช้ตรวจย้อนหลัง (Audit Trail) จากนั้นสร้างรายงาน PDF ด้วย PyMuPDF และ ReportLab การประเมินประสิทธิภาพของโครงงานทำกับชุดทดสอบ 1,000 กรณีตามบทที่ 4 ส่วนระบบเว็บผ่านการทดลองใช้งานกับรายการสมมุติ (เลขที่สิ่งส่งตรวจที่ใช้ทดลอง เช่น 55 และ S-24-1022 ไม่ใช่ข้อมูลผู้ป่วยจริง) รายการที่บันทึกในฐานข้อมูลระหว่างนั้นเป็นผลของการทดลองใช้ ไม่ใช่การทดสอบที่ออกแบบไว้ล่วงหน้า จึงไม่นำมารายงานเป็นผลการทดสอบ

\section{การวิเคราะห์ผล}

\subsection{ตัวชี้วัด}
\begin{itemize}
    \item \textbf{Word Error Rate (WER):} วัดความผิดพลาดระดับคำ
    \begin{equation}
    \mathrm{WER} = \frac{S + D + I}{N} \times 100\%
    \end{equation}
    เมื่อ $S$ คือจำนวนคำที่แทนที่ผิด $D$ คือจำนวนคำที่ตกหล่น $I$ คือจำนวนคำที่เพิ่มเกิน และ $N$ คือจำนวนคำในข้อความเฉลย คำนวณด้วยไลบรารี jiwer หลังทำให้ข้อความเป็นรูปแบบเดียวกัน คือแปลงเป็นตัวพิมพ์เล็ก แทนที่เครื่องหมาย . , ; : ! ? และ - ด้วยช่องว่าง และยุบช่องว่างซ้ำ ดังนั้น 2.5 กลายเป็นสองคำ (2 และ 5) ซึ่งต่างจาก 25 จึงนับเป็นความผิดพลาด ผลรายงานสองเกณฑ์ คือ เกณฑ์ A ตามที่กล่าวนี้ และเกณฑ์ B ที่เพิ่มการปรับรูปแบบการเขียนมิติ (รายละเอียดในบทที่ 4)
    \item \textbf{Character Error Rate (CER):} คำนวณในลักษณะเดียวกับ WER ระดับตัวอักษร
    \item \textbf{เวลาประมวลผล (Latency):} เวลาเฉลี่ยต่อกรณีเป็นวินาที อัตราเร่ง (Speedup) = เวลาของแบบจำลองพื้นฐาน $\div$ เวลาของ PathoWhisper และ Real-Time Factor (RTF) = เวลาประมวลผล $\div$ ความยาวเสียง โดยความยาวเสียงเฉลี่ยคือ 21.48 วินาทีต่อกรณี (วัดด้วย ffprobe) เวลาของ PathoWhisper รวมการกรองเสียงด้วย afftdn (ประมาณ 0.2 วินาที) และการถอดความ
    \item \textbf{ความแม่นยำระดับฟิลด์:} สำหรับแต่ละฟิลด์นับ TP (ค่าที่สกัดได้ตรงกับเฉลย) FP (สกัดค่าที่ไม่ตรง หรือสกัดทั้งที่เฉลยว่าง) FN (ไม่สกัด หรือสกัดไม่ตรงทั้งที่เฉลยมีค่า) และ TN (ว่างทั้งสองด้าน) แล้วคำนวณ Precision $= TP/(TP+FP)$ Recall $= TP/(TP+FN)$ และ F1 รายงานค่าเฉลี่ย F1 แบบ Macro เฉพาะฟิลด์ที่มีกรณีบวกอย่างน้อยหนึ่งกรณี ส่วนฟิลด์ที่ไม่มีกรณีบวกในชุดทดสอบรายงานเฉพาะจำนวนครั้งที่ตัวสกัดคืนค่า (ฟิลด์ควบคุมเชิงลบ) โครงงานไม่ใช้ความถูกต้องรายช่อง (นับช่องที่ว่างทั้งสองด้านเป็นถูก) เป็นตัวชี้วัดหลัก เพราะ 4 จาก 15 ฟิลด์ว่างตลอดทั้งชุดทดสอบ ทำให้ค่าสูงเกินจริง ทั้งสองระบบนำข้อความถอดความผ่านตัวปรับข้อความและตัวสกัดตัวเดียวกันแล้วเทียบกับเฉลย ค่าข้อความเทียบหลังทำให้เป็นรูปแบบเดียวกัน (ตัวพิมพ์เล็ก ตัดขีดกลาง) และค่ามิติเทียบทีละตัวเลข
\end{itemize}
