\section{การประมวลผลและวิเคราะห์ข้อมูล}

\subsection{การประมวลผลเสียงเบื้องต้น}
ไฟล์เสียงถูกกรองด้วย FFmpeg ตามลำดับ คือตัวกรอง \texttt{afftdn} \cite{ffmpeg_afftdn} ด้วยค่าเริ่มต้นของ FFmpeg ได้แก่ ลดสัญญาณรบกวน (\texttt{nr}) 12 dB ระดับเสียงรบกวนพื้นฐาน (\texttt{nf}) $-50$ dB และชนิดเสียงรบกวนแบบขาว (\texttt{nt=w}) แล้วตามด้วย \texttt{silenceremove} ที่ตัดช่วงเงียบต่ำกว่า $-40$ dB ที่ต้นไฟล์ซึ่งยาวเกิน 0.1 วินาที และช่วงหยุดพูดที่ยาวเกิน 0.6 วินาทีตลอดไฟล์ ขั้นตอนนี้ตัดตามระดับสัญญาณ ไม่ใช่แบบจำลองตรวจจับเสียงพูด (VAD) การแปลงเป็น 16 kHz Mono ทำโดยฟังก์ชันโหลดเสียงของไลบรารีถอดความ คำสั่งเต็มอยู่ในภาคผนวก ก โครงงานนี้ไม่ได้ทดลองหรือปรับค่า afftdn อื่น

\subsection{เอนจินถอดความ PathoWhisper}
ใช้ Faster-Whisper รุ่น Small (เวอร์ชัน 1.2.1) \cite{fasterwhisper} บน CTranslate2 \cite{ctranslate2} แบบ INT8 บน CPU 8 เธรด กำหนด Beam Size เป็น 1 และป้อนข้อความนำ (\texttt{PATHOLOGY\_PROMPT}) ที่รวมถ้อยคำและคำศัพท์ตามโปรโตคอล CAP สำหรับมะเร็งเต้านม (ภาคผนวก ก) โครงงานนี้ไม่ได้ Fine-tune น้ำหนักของแบบจำลอง ใช้เพียง Quantization และการปรับพฤติกรรมด้วยข้อความนำ แบบจำลองพื้นฐานคือ Whisper Small จากไลบรารี openai-whisper (PyTorch, FP32 บน CPU, Beam Size 5, ไม่ใช้ Prompt และไม่ผ่าน afftdn) ส่วน PathoWhisper ใช้ Beam Size 1 เวลาที่ลดลงจึงส่วนหนึ่งมาจากการลด Beam Size และการเปรียบเทียบนี้เป็นการเปรียบเทียบทั้งระบบ ไม่ได้แยกผลของแต่ละองค์ประกอบ

\subsection{ตัวสกัดข้อมูลทางคลินิก}
ตัวสกัดใช้นิพจน์ปรกติและกฎหน้าต่างบริบทจับคู่ข้อความกับ 15 ฟิลด์ (รายการอยู่ในภาคผนวก ข) ฟิลด์ส่วนหนึ่ง ได้แก่ ด้านของเต้านม หัตถการ ตำแหน่งก้อน ขนาดก้อน ขอบตัด และต่อมน้ำเหลือง สอดคล้องกับข้อมูลหลักของโปรโตคอล CAP \cite{cap_breast} ส่วนที่เหลือเป็นรายการตรวจสภาพภายนอกที่ใช้ในการบรรยายด้วยตาเปล่า เช่น หัวนม ผิวหนัง และรอยแผลเป็น การแก้ไขกลางประโยคจัดการในขั้นปรับข้อความ (\texttt{normalizer.py}) ด้วยนิพจน์ปรกติที่ตรวจจับคำสัญญาณ sorry, wait, weight, correction, actually และ no wait (รวมคำไทย เช่น แก้เป็น เปลี่ยนเป็น ไม่ใช่ ซึ่งมีทดสอบเพียง 1 กรณี) ที่ตามหลังค่ามิติ เช่น 2.0 x 3.0 x 1.0 cm แล้วเก็บเฉพาะค่าที่พูดหลังคำสัญญาณ ตัวอย่างเช่น 2.0 x 3.0 x 1.0 cm sorry 2.5 x 3.5 x 1.5 cm ได้ผลเป็น 2.5 x 3.5 x 1.5 cm ตัวปรับข้อความมีกฎเพิ่มเติมที่พัฒนาหลังพบข้อบกพร่องจากการทดสอบรอบแรก โดยชุดทดสอบหน่วยปัจจุบันตรวจพฤติกรรมต่อไปนี้ (1) คำว่า weight ที่ตามหลังมิติและตามด้วยน้ำหนักจริง (grams, g, kg) หรือคำว่า margin ไม่ถือเป็นคำสัญญาณ และไม่ลบมิติที่พูดก่อนหน้า (2) คำว่า weight ที่ตามด้วยมิติชุดใหม่ (เช่น 2.0 x 3.0 x 1.0 cm weight 2.5 x 3.5 x 1.5 cm) ถือเป็นการถอดคำว่า wait ผิด และเก็บค่าที่พูดหลัง (3) วลีแก้ไขค่าเดียวที่มีหน่วยทั้งสองฝั่ง เช่น 2 cm no 3 cm ถูกแก้เป็นค่าหลัง (4) คำว่า no ที่ตามด้วยจำนวนต่อมน้ำเหลือง (margin 2 mm no 3 lymph nodes) ไม่ถูกตีเป็นการแก้ไข และ (5) คำว่า actually ในประโยคปกติ และถ้อยคำปฏิเสธ เช่น no residual mass, no discrete mass ต้องไม่ถูกตัด กฎเหล่านี้ทดสอบด้วยการทดสอบหน่วย 16 กรณี (หัวข้อ \ref{sec:unit}) นอกจากนี้ตัวปรับข้อความแทนคำว่า lesion และ tumor ด้วย mass เพราะตัวสกัดใช้คำว่า mass เป็นตัวชี้ตำแหน่งก้อนหลัก คำทั้งสามมีนัยทางพยาธิวิทยาต่างกันเล็กน้อย จึงควรแสดงข้อความถอดความดิบควบคู่กับฟิลด์ที่สกัดเสมอ ตัวสกัดไม่ใช้แบบจำลองภาษาเชิงกำเนิดและไม่เติมค่าที่ไม่ได้ปรากฏในข้อความถอดความ หากไม่พบค่า ฟิลด์จะถูกทิ้งว่างเพื่อให้ผู้ใช้กรอกเอง

\noindent\textbf{การพัฒนาตัวสกัดและความเสี่ยงต่อการปรับตามชุดทดสอบ.} ตัวสกัดและตัวปรับข้อความถูกปรับหลายรอบโดยพิจารณาข้อผิดพลาดที่ปรากฏบนชุดทดสอบ 1,000 กรณีเดียวกับที่ใช้รายงานผล (เช่น รูปแบบเลขที่สิ่งส่งตรวจที่มีขีด เครื่องหมายวรรคตอนหลังขอบตัด และบริบทก่อนคำว่า mass) ทำให้ตัวเลขการสกัดอาจสูงกว่าที่จะได้กับข้อมูลใหม่ รายละเอียดก่อนและหลังการปรับอยู่ในตารางที่ \ref{tab:refine}

\section{การออกแบบและพัฒนาระบบ}

ระบบเป็นเว็บแอปพลิเคชันที่พัฒนาด้วย Flask ให้บริการบนเครื่องผ่าน HTTPS (เซิร์ฟเวอร์ Werkzeug แบบหลายเธรด พอร์ต 7860 ใช้ใบรับรอง TLS ที่ออกเองด้วย OpenSSL) ส่วนหน้าบันทึกเสียงจากไมโครโฟนผ่านเบราว์เซอร์ ส่วนหลังบ้านเรียกขั้นตอนกรองเสียง ถอดความ และสกัดข้อมูล แล้วแสดงผลให้ผู้ใช้ตรวจทานและแก้ไขก่อนยืนยัน ข้อมูลที่ยืนยันแล้วบันทึกลง PostgreSQL 16 ผ่าน Flask-SQLAlchemy และสำรองลง SQLite (\texttt{pathology.db}) โดยสลับไปใช้ SQLite อัตโนมัติเมื่อเชื่อมต่อ PostgreSQL ไม่ได้ จากนั้นสร้างรายงาน PDF และ DOCX ด้วย PyMuPDF และ ReportLab ระบบมีการเข้าสู่ระบบด้วยบัญชีผู้ใช้ (รหัสผ่านถูกแฮช) หน้าประวัติเคส และหน้าแดชบอร์ด การทดสอบระบบประกอบด้วยการทดสอบกรณีทดสอบ 1,000 กรณีตามบทที่ 4 การทดสอบหน่วยของตัวปรับข้อความ 16 กรณี และการทดสอบการทำงานของระบบเว็บ 9 โมดูลด้วยรายการสมมุติ (เลขที่สิ่งส่งตรวจที่ใช้ทดสอบ เช่น 55 และ S-24-1022 ไม่ใช่ข้อมูลผู้ป่วยจริง) ในระหว่างพัฒนาพบว่าจำนวนรายการใน PostgreSQL และ SQLite ไม่เท่ากัน (67 และ 70 รายการ) เพราะเป็นผลของการทดลองใช้ และระบบยังไม่มีกลไกกระทบยอดสองฐานข้อมูล ระบบนี้เป็นต้นแบบสำหรับงานวิจัย ข้อกำหนดที่ต้องมีก่อนใช้งานจริงในโรงพยาบาลอยู่ในบทที่ 5

\section{การวิเคราะห์ผล}

\subsection{ตัวชี้วัด}
\begin{itemize}
    \item \textbf{Word Error Rate (WER):} วัดความผิดพลาดระดับคำ
    \begin{equation}
    \mathrm{WER} = \frac{S + D + I}{N} \times 100\%
    \end{equation}
    เมื่อ $S$ คือจำนวนคำที่แทนที่ผิด $D$ คือจำนวนคำที่ตกหล่น $I$ คือจำนวนคำที่เพิ่มเกิน และ $N$ คือจำนวนคำในข้อความเฉลย คำนวณด้วยไลบรารี jiwer หลังทำให้ข้อความเป็นรูปแบบเดียวกัน คือแปลงเป็นตัวพิมพ์เล็ก แทนที่เครื่องหมาย . , ; : ! ? และ - ด้วยช่องว่าง และยุบช่องว่างซ้ำ ดังนั้น 2.5 กลายเป็นสองคำ (2 และ 5) ซึ่งต่างจาก 25 จึงนับเป็นความผิดพลาด ผลรายงานสองเกณฑ์ คือ เกณฑ์ A ตามที่กล่าวนี้ และเกณฑ์ B ที่เพิ่มการปรับรูปแบบการเขียนมิติ (รายละเอียดในบทที่ 4)
    \item \textbf{เวลาประมวลผล (Latency):} เวลาเฉลี่ยต่อกรณีเป็นวินาที อัตราเร่ง (Speedup) = เวลาของแบบจำลองพื้นฐาน $\div$ เวลาของ PathoWhisper เวลาของ PathoWhisper รวมการกรองเสียงด้วย afftdn (ประมาณ 0.2 วินาที) และการถอดความ
    \item \textbf{การสกัดข้อมูลระดับฟิลด์:} นำข้อความถอดความของแต่ละระบบผ่านตัวสกัดเดียวกันแล้วเทียบกับเฉลยครบ 15 ฟิลด์ ในแต่ละช่องข้อมูลนับ TP (เฉลยมีค่าและสกัดได้ตรง) TN (เฉลยว่างและสกัดได้ว่าง) FN (เฉลยมีค่าแต่สกัดไม่ได้) และ FP (เฉลยว่างแต่สกัดได้ค่า) กรณีสกัดได้ค่าที่ผิดจากเฉลยนับเป็นทั้ง FP และ FN รายงาน (ก) Precision, Recall และ F1 ต่อฟิลด์ และ Macro-F1 ซึ่งเป็นค่าเฉลี่ยเลขคณิตของ F1 ของ 11 ฟิลด์ที่มีค่าบวกในเฉลย (ไม่รวม 4 ฟิลด์ที่ไม่มีค่าบวก) (ข) ความสอดคล้องระดับช่อง (Slot-Level Agreement) $=(\mathrm{TP}+\mathrm{TN})/15{,}000$ ซึ่งเป็นสัดส่วนช่องที่ตรงกับเฉลยจากทั้งหมด 1,000 กรณี $\times$ 15 ฟิลด์ และ (ค) ความจำเพาะ (Specificity) $=\mathrm{TN}/(\mathrm{TN}+\mathrm{FP})$ ของ 4 ฟิลด์ที่ไม่มีค่าบวก

    \item \textbf{อัตราความผิดพลาดวิกฤตต่อเคส (Critical Case Error Rate, $\mathrm{CER}_{\mathrm{case}}$):} พยาธิแพทย์ตรวจทานระดับเคส จึงนับสัดส่วนเคสที่มีฟิลด์วิกฤตอย่างน้อย 1 ฟิลด์ผิด (ค่าผิดหรือว่างทั้งที่มีในเฉลย หรือกรอกทั้งที่เฉลยว่าง) ฟิลด์วิกฤต 6 ฟิลด์ที่ผู้จัดทำกำหนด ได้แก่ ด้านของเต้านม (\texttt{s1\_side}) ขนาดสิ่งส่งตรวจ (\texttt{s3\_dims}) การพบก้อนลุกลาม (\texttt{s10\_infiltrative}) ขนาดก้อน (\texttt{s10\_inf\_dims}) ระยะห่างขอบตัดด้านลึก (\texttt{s11\_deep\_margin}) และการพบต่อมน้ำเหลือง (\texttt{s14\_check}) $\mathrm{CER}_{\mathrm{case}}=\#\text{เคสที่มีฟิลด์วิกฤตผิด}/N\times100\%$ รายงานช่วงความเชื่อมั่นแบบ Wilson 95\% ควบคู่กับ Case-level Exactness $=100\%-\mathrm{CER}_{\mathrm{case}}$ การเปรียบเทียบสองระบบเป็นแบบจับคู่ระดับเคส ใช้ McNemar exact test และ Bootstrap 5,000 รอบ (เมล็ดสุ่ม 42) ของผลต่างแบบจับคู่ รายการฟิลด์วิกฤตกำหนดโดยผู้จัดทำ ควรให้พยาธิแพทย์ยืนยัน
    \item \textbf{ชนิดของความผิดพลาด:} Omission คือเฉลยมีค่าแต่ระบบเว้นว่าง (ผู้ใช้เห็นช่องว่างและกรอกเอง) ส่วน Commission คือระบบกรอกค่าที่ผิดหรือกรอกทั้งที่ไม่มีในเฉลย (ผู้ใช้อาจไม่สังเกต) รายงานจำนวนช่องของทั้งสองชนิด และ Flag Coverage คือสัดส่วนของเคสที่ฟิลด์วิกฤตผิดและระบบแสดงธงเตือนอย่างน้อย 1 ธงจากฟังก์ชัน \texttt{generate\_confidence\_flags()} (ธงเตือนเฉพาะกรณีไม่มีเลขที่สิ่งส่งตรวจ ขนาดสิ่งส่งตรวจไม่ครบ 3 ค่า หรือไม่มีขนาดก้อน และไม่ได้ชี้เฉพาะฟิลด์ที่ผิด)
    \item \textbf{Concept Error Rate (ConER):} สัดส่วนของคำสำคัญทางคลินิกในข้อความอ้างอิง (ตัวเลข สัญลักษณ์มิติและหน่วย และศัพท์ เช่น mastectomy, margin, right, left) ที่ถูกแทนที่ผิดหรือตกหล่น หลังจัดแนวข้อความตามเกณฑ์ B เพราะ WER นับคำทั่วไปเท่ากับตัวเลขหรือด้านของเต้านม
\end{itemize}

ตัวชี้วัดหลักของโครงงานนี้มี 5 ตัว ได้แก่ $\mathrm{CER}_{\mathrm{case}}$ Macro-F1 ของ 11 ฟิลด์ WER เกณฑ์ B ConER และเวลาประมวลผล (มัธยฐานและเปอร์เซ็นไทล์ที่ 95) ส่วนตัวชี้วัดอื่น (WER เกณฑ์ A, ความสอดคล้องระดับช่อง, ความจำเพาะของฟิลด์ที่ไม่มีค่าบวก) เป็นตัวชี้วัดรองเพื่อประกอบการวินิจฉัย


\subsection{การเปรียบเทียบทางสถิติ}
ความลดลงเชิงสัมพัทธ์คำนวณจาก $(\mathrm{WER}_{\text{base}} - \mathrm{WER}_{\text{ours}}) / \mathrm{WER}_{\text{base}}$ และรายงานค่าความแตกต่างเป็นจุดเปอร์เซ็นต์ควบคู่กัน ค่าที่ใช้คือค่าเฉลี่ยของค่ารายกรณี การเปรียบเทียบระหว่างสองระบบจับคู่ระดับกรณี รายงานช่วงความเชื่อมั่น 95\% ด้วย Bootstrap 5,000 รอบ (เมล็ดสุ่ม 42) และทดสอบนัยสำคัญด้วย Wilcoxon signed-rank แบบด้านเดียว ผลรายกรณีทั้ง 2,000 การประมวลผลเก็บเป็นไฟล์ CSV และคำนวณซ้ำด้วยสคริปต์ในภาคผนวก ค เนื่องจาก 1,000 กรณีสร้างจากแม่แบบข้อความชุดเดียวกันและเสียงสังเคราะห์ 2 เสียง กรณีทดสอบจึงไม่เป็นอิสระต่อกันอย่างสมบูรณ์ และค่า $p$ ใช้เพื่อบอกความสม่ำเสมอของความต่างภายในชุดทดสอบนี้ ไม่ใช่เพื่ออนุมานไปยังผู้พูดอื่น ไม่ได้ปรับค่า $p$ สำหรับการเปรียบเทียบหลายหมวด
